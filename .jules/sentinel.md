## 2025-06-25 - DOM-based XSS via innerHTML and Flawed Sanitization
**Vulnerability:** A DOM-based XSS vulnerability existed during PDF ticket generation (`src/lib/ticketGenerator.ts`) because unsanitized user inputs were assigned directly to `innerHTML`. Furthermore, the custom sanitization function `sanitizeHTML` (`src/utils/security.ts`) was flawed, mapping dangerous HTML characters back to themselves (e.g. `<` to `<`) instead of their correct HTML entities.
**Learning:** Even when security utilities exist, their internal implementation must be verified. Functions that construct DOM elements in memory via `innerHTML` (e.g., for `html2canvas` or PDF generation) are just as vulnerable to XSS as elements rendered directly to the screen.
**Prevention:** Always use proper HTML entities (`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#x27;`) in custom replacement maps or rely on established libraries like DOMPurify. Always sanitize dynamic user input before assigning it to `innerHTML`, even for transient DOM elements used strictly for data export or rendering.
