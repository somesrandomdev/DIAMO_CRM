## 2026-04-15 - Fixed XSS vulnerability in ticketGenerator.ts
**Vulnerability:** User-controlled data (via escapeHTML with some bypass edge cases depending on HTML structure and attributes) was directly interpolated into an HTML string and assigned to `container.innerHTML` without a robust sanitization library.
**Learning:** Even if data is escaped before being inserted into an HTML string using basic regex replacements, it might still be vulnerable to XSS due to contextual edge cases or omissions in the custom escape function. The `sanitizeString` function is insufficient.
**Prevention:** Always use a mature, battle-tested sanitization library like `DOMPurify` (using `DOMPurify.sanitize()`) when dynamically injecting HTML content, rather than relying on custom string escaping logic.
## 2024-05-18 - CSV/Formula Injection Prevention
**Vulnerability:** A CSV export function (`exportToCSV` in `HistoriquePage.tsx`) was taking user-controlled input (like client names) and directly interpolating them into a CSV file by joining strings with commas.
**Learning:** If an attacker registers a client with a name like `=CMD|' /C calc'!A0`, it will trigger formula injection and execute arbitrary commands when opened by Excel. CSVs do not inherently protect against this structure manipulation.
**Prevention:** Always sanitize data bound for a CSV export by prepending an apostrophe to strings that start with formula trigger characters (`=`, `+`, `-`, `@`, `\t`, `\r`), and consistently wrap all data fields in double-quotes (escaping internal quotes via `""`) to prevent structural delimiter breakout. Created a `sanitizeForCSV` function for this purpose.
