## 2024-05-18 - DOM-based XSS in Ticket Generation PDF Rendering
**Vulnerability:** User inputs (`kiosque.nom`, `kiosque.adresse`, `client.nom`, `client.telephone`, `offre.nom`) were directly interpolated into an HTML string and assigned to `innerHTML` when building a temporary DOM element for PDF generation using `html2canvas`. This created a DOM-based Cross-Site Scripting (XSS) vulnerability.
**Learning:** Transient DOM elements created for canvas/PDF rendering, even if temporarily appended to the document body, execute scripts when `innerHTML` is updated with raw inputs containing executable HTML/JS payloads. This is a subtle yet critical vector because the elements are not conventionally "rendered" as primary page content but still exist within the active document lifecycle.
**Prevention:** Always use `sanitizeHTML()` from `src/utils/security.ts` (or `DOMPurify.sanitize()`) to safely encode or sanitize user-controlled data before assigning it to `innerHTML`, regardless of whether the element is visible, temporary, or intended solely for a rendering pipeline like `html2canvas`.
