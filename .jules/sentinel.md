## 2024-07-06 - [Critical] Broken XSS sanitization function
**Vulnerability:** The `sanitizeHTML` function had an identity mapping for special characters (e.g., `&` to `&`, `<` to `<`), effectively disabling XSS protection. This allowed XSS payloads to execute, including DOM-based XSS in `ticketGenerator.ts` where user inputs were assigned directly to `innerHTML`.
**Learning:** Hardcoded entity mappings in security functions must be explicitly verified to map to their correct encoded forms (`&amp;`, `&lt;`, etc.), as identity mappings silently bypass protections while appearing fully functional during shallow reviews. Additionally, custom security functions should handle inputs typed as `unknown` (rather than `string`) safely by checking for `null`/`undefined` and casting values via `String()` before proceeding, which prevents XSS payload bypasses through objects or arrays.
**Prevention:** 1) Always verify custom HTML encoding mappings output the correct escaped string entities (`&amp;`, `&lt;`, etc.). 2) Type security input parameters as `unknown` and handle coercion carefully (`String(input)`). 3) Apply `sanitizeHTML` universally when setting `innerHTML`, even on transient DOM nodes.
